# 6장: MVP에서 스케일업까지 — 검증 후 확장하는 단계별 전략

## 왜 MVP부터 시작해야 하는가

CB Insights의 분석에 따르면, 스타트업 실패 원인 1위는 **"시장이 필요로 하지 않는 제품을 만든 것"**(42%)입니다. 수개월, 수년을 투자해 완벽한 제품을 만들었는데 고객이 원하지 않는다면? 되돌릴 수 없는 시간과 비용의 낭비입니다.

**MVP(Minimum Viable Product, 최소 기능 제품)**는 이 리스크를 최소화하는 방법입니다. 핵심 가치만 담은 최소한의 제품으로 시장 반응을 확인한 후, **검증된 방향으로 확장**하는 전략입니다.

## MVP의 종류

모든 MVP가 실제 제품일 필요는 없습니다:

### 1. 랜딩 페이지 MVP
제품이 없는 상태에서 랜딩 페이지만 만들어 **수요를 테스트**합니다.
- 사전 등록 페이지 → 이메일 수집
- 핵심 지표: 방문자 대비 등록 전환율
- 비용: 거의 0원 (노코드 도구 활용)

### 2. 오즈의 마법사 MVP (Wizard of Oz)
겉으로는 자동화된 서비스처럼 보이지만, **뒤에서 사람이 수동으로 운영**합니다.
- 초기 배달의민족: 앱으로 주문받고, 전화로 음식점에 전달
- 핵심: 기술 개발 전에 비즈니스 모델 검증

### 3. 컨시어지 MVP (Concierge)
소수의 고객에게 **수동으로 직접 서비스**를 제공합니다.
- 초기 토스: 소수 사용자에게 직접 송금 서비스 제공하며 UX 검증
- 핵심: 고객과의 밀착으로 깊은 인사이트 확보

### 4. 기능 축소 MVP (Single Feature)
핵심 기능 딱 하나만 구현합니다.
- 초기 당근마켓: 동네 중고거래 게시판 기능만
- 핵심: "이것 하나만은 완벽하게"

## MVP 설계 프레임워크

### Step 1: 핵심 가설 정의

```
가설 문장 작성:
"[타겟 고객]은 [문제 상황]에서 [우리 솔루션]을 사용하면
[기대 결과]를 얻을 것이다."

예시:
"20~30대 직장인은 점심 메뉴 선택에 어려움을 겪을 때
AI 추천 서비스를 사용하면 5분 안에 만족스러운 선택을 할 것이다."
```

### Step 2: 핵심 기능 우선순위

**MoSCoW 프레임워크**를 사용합니다:

| 분류 | 의미 | MVP 포함 |
|------|------|----------|
| **Must Have** | 없으면 제품이 작동하지 않음 | O |
| **Should Have** | 중요하지만 없어도 사용 가능 | X (v2에서) |
| **Could Have** | 있으면 좋지만 필수 아님 | X (v3에서) |
| **Won't Have** | 이번에는 하지 않음 | X |

### Step 3: 성공/실패 기준 설정

MVP 출시 전에 반드시 **숫자로 된 기준**을 정하세요:

```
성공 기준 예시:
- 2주 내 사전 등록 500명 이상
- 첫 달 유료 전환율 5% 이상
- NPS 점수 40 이상
- 재방문율 30% 이상

실패 기준:
- 위 기준의 50% 미만이면 피벗 검토
- 위 기준의 30% 미만이면 중단 결정
```

## 고객 피드백 루프

### 피드백 수집 → 분석 → 반영 사이클

```
[Build] → [Measure] → [Learn] → [Build] ...
 제작        측정         학습       개선

이 사이클을 가능한 빠르게 돌리는 것이 핵심
목표: 1사이클 = 1~2주
```

### 피드백 수집 방법

| 방법 | 장점 | 단점 | 적합한 단계 |
|------|------|------|-------------|
| **사용자 인터뷰** | 깊은 인사이트 | 시간 소요 | MVP 초기 |
| **설문 조사** | 대량 수집 | 깊이 부족 | 성장기 |
| **행동 데이터** | 객관적, 실시간 | 이유를 알 수 없음 | 전 단계 |
| **A/B 테스트** | 과학적 검증 | 트래픽 필요 | 스케일업 |
| **NPS 조사** | 추천 의향 파악 | 단순 지표 | 전 단계 |

### 한국에서 효과적인 피드백 채널

- **카카오톡 오픈채팅**: 소규모 베타 사용자 커뮤니티
- **네이버 카페/밴드**: 중장년층 사용자 피드백
- **인스타그램 DM/스토리**: MZ세대 피드백
- **배민 리뷰 시스템**: 별점 + 텍스트 리뷰의 한국형 피드백 모델

## 스케일업의 5단계

MVP가 검증되었다면, 이제 확장할 차례입니다.

### Stage 1: Product-Market Fit 확인 (0→1)

**기준**: 사용자의 40% 이상이 "이 제품이 없으면 매우 아쉬울 것"이라고 답할 때

배달의민족의 PMF 순간: 주문량이 자체 처리 능력을 초과하기 시작한 시점. **"감당이 안 될 정도로 주문이 몰린다"는 것이 PMF의 신호**입니다.

### Stage 2: 반복 가능한 성장 채널 확보 (1→10)

PMF를 확인했다면, **돈을 넣으면 성장이 나오는 채널**을 찾아야 합니다.

```
성장 방정식:
CAC(고객 획득 비용) < LTV(고객 생애 가치) × 1/3

예시:
LTV: 300,000원
허용 CAC: 100,000원 이하
```

### Stage 3: 운영 체계 구축 (10→100)

- SOP 문서화 (5장 참고)
- 핵심 인력 채용
- 기술 인프라 확장 (오토스케일링)
- 고객 지원 체계 구축

### Stage 4: 시장 확장 (100→1,000)

| 확장 방향 | 설명 | 한국 사례 |
|-----------|------|-----------|
| **지역 확장** | 새로운 지역으로 | 당근마켓: 동네→전국→글로벌 |
| **제품 확장** | 새로운 제품/서비스 | 토스: 송금→투자→보험→대출 |
| **고객 확장** | 새로운 고객 세그먼트 | 무신사: 남성→여성→키즈 |
| **채널 확장** | 새로운 유통 채널 | 네이버: 검색→쇼핑→금융 |

### Stage 5: 생태계 구축 (1,000→∞)

플랫폼이 되는 단계입니다. 다른 사업자들이 우리 위에서 비즈니스를 하는 생태계를 만듭니다.

- **카카오**: 메신저 → 택시/쇼핑/금융/콘텐츠 생태계
- **네이버**: 검색 → 스마트스토어/웹툰/금융 생태계

## Netflix의 스케일업 여정

Netflix는 MVP에서 글로벌 스케일까지의 교과서적 사례입니다:

| 단계 | 시기 | 모델 | 핵심 전략 |
|------|------|------|-----------|
| MVP | 1997 | DVD 우편 배송 | 온라인 주문의 편의성 검증 |
| PMF | 1999 | 월정액 구독 | 연체료 없는 구독의 매력 확인 |
| 스케일 | 2007 | 스트리밍 전환 | DVD→디지털로 기술 전환 |
| 확장 | 2013 | 오리지널 콘텐츠 | 하우스 오브 카드 성공 |
| 생태계 | 2016~ | 글로벌 플랫폼 | 190개국 동시 서비스 |

**핵심 교훈**: 각 단계에서 **이전 모델을 과감히 버리고** 다음 모델로 전환한 용기가 Netflix를 만들었습니다.

## 스케일업 시 흔한 실수

1. **PMF 없이 스케일**: 검증 없이 마케팅비를 퍼붓는 것 → "밑 빠진 독에 물 붓기"
2. **조기 최적화**: 사용자 100명일 때 1,000만 명용 인프라 구축 → 자원 낭비
3. **핵심 가치 희석**: 확장하면서 원래 잘하던 것을 소홀히 함
4. **조직 문화 무시**: 10명 → 100명으로 갈 때 문화 관리 실패
5. **캐시카우 의존**: 기존 수익원에 안주하여 혁신 중단

### 핵심 정리

> **완벽한 제품을 만들기 전에, 고객이 원하는 것인지 먼저 검증하세요.** MVP로 시작하고, 피드백 루프로 개선하고, PMF를 확인한 후에 스케일업하세요. 다음 장에서는 검증 결과 방향 전환이 필요할 때, 어떻게 피벗해야 하는지를 다루겠습니다.
