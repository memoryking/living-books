# 5장: 린 운영과 비용 구조 — 수익성을 극대화하는 비용 관리

## 수익의 두 가지 레버

수익성을 높이는 방법은 두 가지뿐입니다: **매출을 늘리거나, 비용을 줄이거나.** 앞의 장들이 매출 측면(수익 모델, 가치 제안, 가격)을 다뤘다면, 이 장은 **비용 측면의 최적화**를 다룹니다.

**린(Lean) 운영**이란 낭비를 제거하고 가치 창출에 집중하는 운영 철학입니다. 도요타 생산 방식(TPS)에서 시작된 이 개념은 이제 스타트업과 디지털 비즈니스의 핵심 운영 원칙이 되었습니다.

## 비용 구조의 이해

### 고정비 vs 변동비

| 구분 | 고정비 | 변동비 |
|------|--------|--------|
| 정의 | 매출과 무관하게 발생 | 매출에 비례해 발생 |
| 예시 | 임대료, 정규직 급여, 서버 기본료 | 원재료비, 배송비, 수수료 |
| 특징 | 예측 가능, 규모의 경제 | 유연, 리스크 낮음 |

### 비용 구조 유형

**1. 비용 주도형 (Cost-Driven)**
- 최저 비용 달성이 핵심 경쟁력
- 예: 쿠팡(물류 효율화), 다이소(원가 절감)

**2. 가치 주도형 (Value-Driven)**
- 프리미엄 가치 제공에 집중, 비용은 부차적
- 예: 애플(디자인·경험), 배달의민족(브랜딩)

### 한국 스타트업의 비용 구조 벤치마크

초기 스타트업(시드~시리즈A)의 건강한 비용 구조:

```
인건비: 50~60%
마케팅: 15~25%
인프라(서버, SaaS 도구): 10~15%
기타(사무실, 법무 등): 10~15%
```

**핵심 원칙**: 초기에는 **인건비 비중이 높은 것이 정상**입니다. 다만, 매출 성장에 따라 인건비 비율이 점진적으로 줄어야 합니다.

## 린 운영의 7가지 낭비 제거

도요타가 정의한 7가지 낭비를 디지털 비즈니스에 적용하면:

| 낭비 유형 | 제조업 예시 | 디지털 비즈니스 예시 |
|-----------|-------------|---------------------|
| 과잉 생산 | 재고 과다 | 사용되지 않는 기능 개발 |
| 대기 | 공정 대기 | 의사결정 지연, 승인 병목 |
| 운반 | 불필요한 이동 | 데이터 이관, 수작업 전달 |
| 과잉 처리 | 불필요한 가공 | 과도한 보고서, 불필요한 회의 |
| 재고 | 원자재 재고 | 미완성 프로젝트, 기술 부채 |
| 동작 | 불필요한 움직임 | 비효율적 워크플로우 |
| 결함 | 불량품 | 버그, 고객 불만, 환불 |

## 팀 구성과 인력 최적화

### Skills Mapping (역량 매핑)

팀원의 역량을 시각화하여 **중복과 공백**을 파악합니다:

```
           마케팅  개발  디자인  기획  데이터
팀원 A:     ★★★   ★    ★★     ★★★★  ★★
팀원 B:     ★     ★★★★  ★★     ★★    ★★★
팀원 C:     ★★    ★★   ★★★★   ★★    ★
팀원 D:     ★★★★  ★    ★      ★★★   ★★★★

→ 디자인 역량 부족 발견 → 외주 또는 충원 결정
```

### Cross-Training (교차 훈련)

핵심 역량을 2명 이상이 수행할 수 있도록 훈련합니다. **한 사람이 빠지면 전체가 멈추는 SPOF(Single Point of Failure)를 방지**하기 위함입니다.

특히 한국 스타트업에서 흔한 문제: "그 업무는 XX님만 할 수 있어요." 이 상황이 되면 이미 리스크입니다.

## KPI 기반 운영 최적화

### OKR과 KPI의 차이

- **OKR (Objectives & Key Results)**: 방향성과 야심찬 목표 ("월 매출 10억 달성")
- **KPI (Key Performance Indicators)**: 측정 가능한 핵심 지표 ("전환율 3.5%, CAC 15,000원")

### 린 운영의 핵심 KPI

| KPI | 공식 | 건강한 수준 |
|-----|------|-------------|
| **매출총이익률** | (매출 - 원가) / 매출 | 60% 이상 (SaaS) |
| **운영비율** | 운영비 / 매출 | 70% 이하 |
| **고객당 비용** | 총 운영비 / 고객 수 | 지속적 감소 추세 |
| **직원당 매출** | 매출 / 직원 수 | 지속적 증가 추세 |
| **번레이트** | 월간 순 현금 소진 | 런웨이 18개월 이상 |

### 번레이트와 런웨이

```
번레이트(Burn Rate) = 월간 지출 - 월간 수입

런웨이(Runway) = 보유 현금 / 번레이트

예시)
보유 현금: 3억 원
월 지출: 5,000만 원
월 수입: 2,000만 원
번레이트: 3,000만 원
런웨이: 10개월

→ 10개월 안에 손익분기점 달성 또는 추가 투자 필요
```

## SOP (Standard Operating Procedures) 구축

### SOP가 필요한 이유

같은 업무를 매번 다르게 수행하면 **품질 편차**가 생기고, **교육 비용**이 증가합니다.

### SOP 작성 프레임워크

```
[SOP 제목]: 고객 문의 응대 프로세스

목적: 고객 문의에 24시간 이내 응대하여 만족도 90% 이상 유지

단계:
1. 문의 접수 (채널: 카카오톡, 이메일, 전화)
2. 카테고리 분류 (제품, 배송, 환불, 기타)
3. 1차 응대 (템플릿 기반, 30분 이내)
4. 해결 불가 시 에스컬레이션 (담당자 지정)
5. 해결 후 만족도 조사 발송
6. 주간 리포트 작성

담당자: CS팀
갱신 주기: 월 1회
```

## 공급망 관리와 JIT

### JIT (Just-In-Time) 원칙

필요한 것을, 필요한 때에, 필요한 만큼만 확보하는 원칙입니다.

### 한국 이커머스에서의 JIT 적용

**전통적 방식**: 상품 100개 미리 구매 → 재고 보관 → 판매

**JIT 방식 (무재고 모델)**:
1. 주문 접수
2. 공급사에 발주
3. 고객에게 직배송

네이버 스마트스토어에서 **위탁판매(드롭쉬핑)** 모델이 이에 해당합니다. 재고 리스크를 0으로 만들 수 있지만, 배송 속도와 품질 관리가 과제입니다.

### 쿠팡의 역발상: 재고를 무기로

반면 쿠팡은 JIT의 반대 전략을 택했습니다. 대규모 물류 센터에 직매입 재고를 쌓고, **로켓배송이라는 고객 가치**로 전환했습니다. 비용이 많이 들지만, 이것이 바로 **해자(Moat)**가 되었습니다.

핵심 교훈: **비용 절감이 항상 답은 아닙니다. 전략적 비용 투자가 경쟁 우위를 만들기도 합니다.**

## 기술 인프라 비용 최적화

### 클라우드 비용 관리

| 전략 | 설명 | 절감 효과 |
|------|------|-----------|
| 예약 인스턴스 | 1~3년 약정 할인 | 30~60% |
| 오토스케일링 | 트래픽에 따라 자동 조절 | 20~40% |
| 스팟 인스턴스 | 미사용 자원 저가 활용 | 60~90% |
| 서버리스 | 사용한 만큼만 과금 | 변동폭 큼 |

### SaaS 도구 비용 감사

분기마다 사용 중인 SaaS 도구를 점검하세요:
- 실제 사용률이 50% 미만인 도구 → 다운그레이드 또는 해지
- 기능이 겹치는 도구 → 하나로 통합
- 연간 결제 전환 시 할인 → 20~30% 절감
