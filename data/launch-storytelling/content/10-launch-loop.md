# 런칭 루프: 반복할수록 강해지는 성장 엔진

## 한 번의 런칭으로 끝내지 마세요

첫 번째 런칭을 성공적으로 마쳤다면, 축하합니다. 하지만 진짜 질문은 이것입니다. **"두 번째, 세 번째 런칭도 성공할 수 있는가?"**

대부분의 사업자는 런칭을 **일회성 이벤트**로 취급합니다. 모든 에너지를 쏟아붓고, 끝나면 탈진 상태로 돌아갑니다. 3개월 후 다시 런칭할 때는 처음부터 다시 시작합니다. 이것은 지속 가능하지 않습니다.

**런칭 루프(Launch Loop)**는 한 번의 런칭 경험이 다음 런칭의 자산이 되는 **반복 가능한 성장 엔진**입니다.

## 런칭 루프 사이클

런칭 루프는 4단계로 구성됩니다. 각 단계가 다음 단계의 연료가 됩니다.

```
 ┌────────────────────────────────────────┐
 │                                        │
 ▼                                        │
[Build] ──→ [Launch] ──→ [Learn] ──→ [Optimize]
 준비          실행         학습         최적화
 │                                        ▲
 │                                        │
 └────────────────────────────────────────┘
```

### 1단계: Build (준비)
이전 런칭의 데이터와 피드백을 바탕으로 다음 제품/버전을 설계합니다. 처음부터 만드는 것이 아니라, **기존 자산을 활용**합니다.

### 2단계: Launch (실행)
4-7장에서 배운 프리런칭~D-Day 프로세스를 실행합니다. 두 번째부터는 이미 이메일 리스트, 커뮤니티, 콘텐츠 자산이 있으므로 훨씬 효율적입니다.

### 3단계: Learn (학습)
9장의 KPI와 코호트 분석으로 **무엇이 효과가 있었고 없었는지**를 정확히 파악합니다.

### 4단계: Optimize (최적화)
학습 결과를 바탕으로 프로세스를 개선합니다. ICE 프레임워크로 실험 우선순위를 정합니다.

## ICE 실험 프레임워크

모든 것을 한꺼번에 바꿀 수는 없습니다. **어떤 개선을 먼저 할 것인가**를 결정하는 도구가 ICE 프레임워크입니다.

| 요소 | 질문 | 점수 (1-10) |
|------|------|------------|
| **Impact (영향력)** | 이 변화가 핵심 KPI에 얼마나 영향을 줄 것인가? | |
| **Confidence (확신도)** | 이 변화가 효과가 있을 것이라는 확신이 얼마나 있는가? | |
| **Ease (용이성)** | 이 변화를 실행하는 데 얼마나 쉬운가? (시간, 비용, 기술) | |

**ICE 점수 = (Impact + Confidence + Ease) / 3**

### ICE 실험 예시

| 실험 아이디어 | I | C | E | ICE 점수 | 우선순위 |
|-------------|---|---|---|---------|---------|
| 이메일 제목줄 A/B 테스트 | 7 | 8 | 9 | 8.0 | 1 |
| 랜딩페이지 영상 추가 | 8 | 6 | 5 | 6.3 | 3 |
| 카카오톡 시퀀스 추가 | 7 | 7 | 7 | 7.0 | 2 |
| 전면 리브랜딩 | 9 | 4 | 2 | 5.0 | 4 |

ICE 점수가 높은 것부터 실행합니다. **한 번에 하나의 실험만** 진행하세요. 여러 변수를 동시에 바꾸면 어떤 것이 효과를 냈는지 알 수 없습니다.

## 마이크로 런칭: 작게, 자주, 빠르게

대규모 런칭을 연 1-2회만 한다면, 그 사이에 **마이크로 런칭**을 활용하세요.

### 마이크로 런칭이란?

기존 제품의 새로운 버전, 보너스 콘텐츠, 시즌 한정 상품 등을 **소규모로 빠르게** 출시하는 것입니다.

**마이크로 런칭 예시:**
- 기존 온라인 강의에 **보너스 모듈 추가** → 기존 구매자 업셀, 신규 고객 유입 기회
- **시즌 한정 번들** → 겨울 시즌 패키지, 새해 목표 패키지
- **무료 챌린지** → 5일 챌린지로 새 구독자 획득 + 유료 제품 연결
- **라이브 워크숍** → 한정 인원 실시간 세션, 녹화본은 추후 판매

### 마이크로 런칭의 장점

1. **리스크 최소화**: 작은 규모이므로 실패해도 타격이 적습니다
2. **빠른 피드백**: 고객 반응을 빠르게 확인하고 본 런칭에 반영
3. **리스트 활성화**: 이메일 구독자와의 관계를 유지하는 터치포인트
4. **매출 공백 메우기**: 대규모 런칭 사이의 매출 공백을 채웁니다

## 연간 런칭 캘린더 설계

계획 없이 "때 되면 하자"는 가장 위험한 전략입니다. 연간 런칭 캘린더를 미리 설계하세요.

### 캘린더 설계 원칙

1. **대규모 런칭은 연 2-3회**: 에너지와 자원이 집중되는 시기
2. **마이크로 런칭은 분기별 1-2회**: 대규모 런칭 사이 모멘텀 유지
3. **한국 시즌을 활용**: 새해(1월), 봄(3-4월), 추석(9월), 연말(11-12월)
4. **프리런칭 기간 3주 확보**: 역산해서 콘텐츠 제작 시작일 설정

### 연간 캘린더 예시

| 월 | 활동 | 유형 |
|---|------|------|
| 1월 | 새해 목표 챌린지 | 마이크로 런칭 |
| 2-3월 | 봄 시즌 프리런칭 준비 | Build |
| 4월 | 메인 제품 2.0 런칭 | 대규모 런칭 |
| 5월 | 데이터 분석, 최적화 | Learn + Optimize |
| 6월 | 여름 한정 번들 | 마이크로 런칭 |
| 7-8월 | 가을 시즌 프리런칭 준비 | Build |
| 9월 | 신규 제품 런칭 | 대규모 런칭 |
| 10월 | 데이터 분석, 최적화 | Learn + Optimize |
| 11월 | 블랙프라이데이/연말 프로모션 | 마이크로 런칭 |
| 12월 | 연말 번들 + 내년 계획 | 마이크로 런칭 + Build |

## 80/20 재활용 원칙

파레토 법칙을 런칭에 적용합니다. **성과의 80%는 콘텐츠의 20%에서 나옵니다.** 그 20%를 찾아서 반복적으로 활용하세요.

실전 적용법:
1. 이전 런칭에서 **전환율 상위 20% 콘텐츠**를 추출합니다
2. 그 콘텐츠의 **구조와 앵글**을 분석합니다 (왜 효과가 있었는지)
3. 다음 런칭에서 **같은 구조, 새로운 내용**으로 재활용합니다
4. 나머지 80%는 과감히 버리거나 최소한의 에너지로 처리합니다

## 팀 번아웃 방지

런칭은 고강도 작업입니다. 혼자 하든 팀으로 하든, **번아웃 방지**를 시스템에 포함시켜야 합니다.

### 번아웃 방지 5가지 원칙

1. **런칭 후 리커버리 주간**: 대규모 런칭 후 1주일은 가벼운 업무만. 이것을 캘린더에 미리 블록합니다.
2. **자동화 우선**: 반복 작업은 도구로 자동화. 사람이 할 일은 판단과 창의력이 필요한 것만.
3. **체크리스트 문화**: 매번 새로 생각하지 않고, 검증된 체크리스트를 따릅니다.
4. **에너지 관리**: 런칭 주간에는 다른 프로젝트를 모두 정지합니다.
5. **회고 미팅**: 런칭 후 3일 이내에 "잘한 점, 개선할 점, 다음에 시도할 것"을 기록합니다. 기억이 생생할 때 해야 합니다.

- [ ] 마이크로 런칭 아이디어 최소 2개 브레인스토밍
- [ ] 연간 런칭 캘린더 초안 작성

- [ ] 런칭 후 리커버리 주간 캘린더에 미리 블록
