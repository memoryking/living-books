# Chapter 7. 팔리는 글의 구조: 문제→해결→증거→행동 프레임워크

## 구조 없는 글은 무너진다

좋은 재료가 있어도 레시피가 없으면 요리가 안 되듯이, 좋은 정보가 있어도 **구조가 없으면 글이 안 됩니다**. 독자가 끝까지 읽고 행동하게 만드는 글에는 반드시 뼈대가 있습니다.

이 챕터에서는 검증된 4가지 글쓰기 구조를 배우고, 플랫폼별로 어떻게 적용하는지 실전 템플릿까지 가져가실 수 있습니다.

## 핵심 구조: 문제→해결→증거→행동 (PSEA)

가장 강력하고 보편적인 설득 글쓰기 구조입니다. 이 구조 하나만 익혀도 모든 플랫폼에서 써먹을 수 있어요.

### P — Problem (문제 제기)

**독자의 고통을 대신 말해주세요.** "이 사람 내 상황을 아는구나"라는 생각이 드는 순간 신뢰가 시작됩니다.

**문제 제기 패턴:**
| 패턴 | 예시 |
|---|---|
| 직접 질문 | "블로그에 글을 올려도 조회수 10 넘기기가 이렇게 어려운 건가요?" |
| 상황 묘사 | "매일 2시간씩 글을 쓰는데, 댓글은 0. 좋아요도 0." |
| 통계 활용 | "블로그를 시작한 사람의 93%가 3개월 안에 포기합니다." |
| 반직관 | "많이 쓸수록 오히려 조회수가 떨어지는 이유, 아시나요?" |

**문제 제기 핵심 원칙:**
1. **독자의 언어로 쓰세요** — 전문 용어가 아니라 독자가 실제로 쓰는 말
2. **감정까지 건드리세요** — "조회수가 낮다"가 아니라 "허무하다, 답답하다"
3. **구체적인 상황을 그리세요** — 독자가 "맞아, 이거 내 얘기야"라고 느끼게

### S — Solution (해결책 제시)

**문제를 해결할 핵심 방법을 제시합니다.** 여기서 중요한 건 "무엇"과 "어떻게"를 모두 알려주는 것.

**해결책 제시 패턴:**
```
"이 문제의 핵심은 [원인]에 있습니다.
해결법은 의외로 간단해요.
[핵심 방법]을 적용하면 됩니다.
구체적으로 말하면..."
```

**해결책 작성 팁:**
1. **단계별로 쪼개세요** — "3단계로 해결" 같은 구조가 소화하기 쉽습니다
2. **당장 실행 가능하게** — "마인드셋을 바꿔라"는 모호, "오늘 15분 필사하라"는 구체적
3. **왜 이 방법인지 설명** — 다른 방법이 아닌 이 방법을 추천하는 이유

### E — Evidence (증거 제시)

**말만 하면 안 됩니다. 증거를 보여줘야 합니다.**

| 증거 유형 | 신뢰도 | 활용 예시 |
|---|---|---|
| **데이터/통계** | ★★★★★ | "이 방법 적용 후 전환율 3.2배 상승" |
| **실제 사례** | ★★★★★ | "A씨는 이 방법으로 3개월 만에 월 매출 500만 원 달성" |
| **전문가 인용** | ★★★★ | "마케팅 전문가 OOO 교수도 이 방법을 추천합니다" |
| **비포&애프터** | ★★★★★ | "적용 전 방문자 50명 → 적용 후 방문자 3,000명" |
| **본인 경험** | ★★★ | "저도 직접 해봤는데, 결과는..." |
| **논리적 추론** | ★★ | "A이면 B이고, B이면 C이므로..." |

**증거 제시 핵심:**
- **숫자를 쓰세요** — "많이 올랐다" (X) → "237% 상승했다" (O)
- **비교를 보여주세요** — Before/After가 가장 강력
- **3개 이상의 증거를 제시하세요** — 증거가 많을수록 설득력 상승

### A — Action (행동 유도)

**읽기만 하고 끝나면 안 됩니다.** 독자가 다음에 해야 할 행동을 명확하게 알려주세요.

**행동 유도 3단계 공식:**

```
Step 1: 행동 안내 — "지금 바로 [구체적 행동]을 해보세요"
Step 2: 장벽 제거 — "딱 5분이면 됩니다 / 무료입니다 / 쉽습니다"
Step 3: 미래 약속 — "[행동]하면 [긍정적 결과]를 얻게 됩니다"
```

## PSEA 구조 실전 템플릿

### 네이버 블로그용 (1,500~2,000자)

```
[제목] 6가지 헤드라인 공식 중 선택

[P - 문제] (200자)
독자의 고통을 공감 + 질문

[S - 해결] (800자)
핵심 방법 3단계 설명
각 단계마다 구체적 예시

[E - 증거] (300자)
실제 사례 1개 + 데이터 1개

[A - 행동] (200자)
CTA + 이웃 추가/공감 유도
```

### 인스타 캡션용 (500자 이내)

```
[P] 한 줄 문제 제기
[S] 해결법 핵심 1~3줄
[E] 미니 사례 or 숫자 1개
[A] "저장해두세요" / "댓글로 알려주세요"
```

### 스마트스토어 상세페이지용

```
[P] 고객의 고통 3가지 나열 (공감)
[S] 이 제품이 해결하는 방법 (기능→혜택 변환)
[E] 후기 + 인증 + 데이터
[A] 구매 버튼 + 긴급성(한정 수량/기간)
```

## 추가 글쓰기 구조 3가지

PSEA 외에도 상황에 따라 활용할 수 있는 구조들입니다.

### 구조 2: AIDA (Attention → Interest → Desire → Action)

마케팅의 고전 프레임워크를 글쓰기에 적용한 것입니다.

| 단계 | 역할 | 글쓰기 적용 |
|---|---|---|
| **A**ttention | 주의 끌기 | 강력한 헤드라인 + 훅 |
| **I**nterest | 흥미 유지 | 독자 관련 정보 + 스토리 |
| **D**esire | 욕구 자극 | 혜택 + 변화된 미래 묘사 |
| **A**ction | 행동 유도 | 명확한 CTA |

### 구조 3: PAS (Problem → Agitate → Solution)

문제를 더 악화시켜서 해결의 필요성을 극대화하는 구조.

**예시:**
```
[P] "상세페이지 전환율이 0.3%밖에 안 됩니다."
[A] "이대로 가면 광고비만 태우고 매출은 제자리. 
    경쟁사는 같은 키워드에서 전환율 3%를 찍고 있어요.
    매달 수백만 원의 차이가 여기서 발생합니다."
[S] "해결법은 상세페이지의 첫 3줄을 바꾸는 겁니다."
```

### 구조 4: FAB (Features → Advantages → Benefits)

제품/서비스 소개에 최적화된 구조입니다.

| 단계 | 의미 | 예시 (온라인 강의) |
|---|---|---|
| **F**eature | 기능/특징 | "10개의 글쓰기 템플릿 제공" |
| **A**dvantage | 장점 | "글 쓰는 시간이 절반으로 줄어듦" |
| **B**enefit | 혜택 | "남는 시간에 콘텐츠를 2배 더 생산 가능" |

**핵심**: Feature에서 멈추지 말고, 반드시 Benefit까지 연결하세요.
- (X) "이 강의는 20강으로 구성되어 있습니다" (Feature에서 멈춤)
- (O) "20강의 체계적인 커리큘럼으로, 한 달 후에는 상세페이지를 혼자 쓸 수 있게 됩니다" (Benefit까지 연결)

## 페이싱(Pacing): 글의 속도 조절

좋은 글은 빠른 부분과 느린 부분이 번갈아 나옵니다. **페이싱**은 글의 속도를 의도적으로 조절하는 기술입니다.

### 속도 조절 도구

| 요소 | 속도 효과 | 사용 시점 |
|---|---|---|
| 짧은 문장 | 빠름 ▲ | 강조, 전환, 긴급 |
| 긴 문장 | 느림 ▼ | 설명, 스토리, 분위기 |
| 줄바꿈 | 빠름 ▲ | 시각적 쉼표, 강조 |
| 리스트/표 | 보통 → | 정보 정리, 비교 |
| 질문 | 멈춤 ■ | 생각 유도, 전환 |
| 따옴표/인용 | 느림 ▼ | 권위, 감정 |

### 페이싱 적용 예시

```
[느림] 2022년 여름, 저는 매일 새벽 5시에 일어나 블로그 글을 썼습니다.
아이들이 일어나기 전 2시간이 제가 가진 유일한 시간이었으니까요.

[빠름] 3개월.
90편의 글.
조회수? 평균 23.

[멈춤] 포기할까요?

[느림] 아닙니다. 저는 91번째 글에서 모든 걸 바꿨습니다.
제목 짓는 법 하나를 배운 거예요.

[빠름] 결과는 폭발적이었습니다.
일주일 만에 조회수 15,000.
첫 체험단 제안.
첫 수익.
```

|---|---|---|
| | | |

---

> **핵심 정리**: 문제→해결→증거→행동(PSEA)이 글의 기본 뼈대입니다. AIDA, PAS, FAB를 상황에 맞게 활용하고, 페이싱으로 속도를 조절하세요. 구조가 있는 글은 절대 길을 잃지 않습니다.
