# 기능 변경 시 학습 안내 동시 갱신

사용자 요청에 따라 기능 변경에는 안내 갱신이 기본으로 포함된다. 안내 갱신을 위해 별도 허락이나 재요청을 기다리지 않는다. 이 문서는 작업 절차이며 코드 변경을 감지하는 자동 집필 서비스가 아니다.

## 함께 관리할 파일

- 학습 동작: `src/components/hanja/HanjaReader.tsx`, `WritingPad.tsx`, `src/lib/hanja-study.ts`.
- 사용자 안내: `src/components/hanja/StudyGuide.tsx`. 기록 가져오기/내보내기 조작은 `HanjaReader.tsx`에 있다.
- 안내 이미지: `data/hanja-memory/guide-screens.json`과 해당 R2 객체.
- 캡처/업로드: `scripts/capture-hanja-guide.mjs`, `scripts/upload-hanja-guide.mjs`.
- 검증: `scripts/qa-hanja-guide.mjs`, 변경 기능에 맞는 QA 및 일정 검사.
- 구현 문서: `data/hanja-memory/README.md`; 재사용 규칙: `docs/skills/memory-learning-ebook-set/`.

## 작업 순서

1. 기능 변경 범위와 실제 동작을 확인한다. 기존 안내에서 관련 설명·버튼 이름·예시·FAQ·주의사항·캡처를 찾는다.
2. 기능과 안내를 함께 수정한다. 특히 ‘언제 저장되는지’, ‘다음 일정이 유지되는지’, ‘목록에서 언제 빠지는지’, ‘중간에 나가면 어떻게 되는지’를 실제 코드와 맞춘다. 변경되지 않은 내용은 유지한다.
3. 안내 대상 UI가 바뀌면 수정된 화면에서 부분 캡처를 만든다. 기본 캡처 스크립트가 운영 주소를 사용하므로 배포 전 작업에서는 주소를 로컬 또는 검증용 주소로 바꿔 최신 화면을 캡처한다. 오래된 운영 화면을 새 기능 안내로 사용하지 않는다.
4. 별도 브라우저 프로필과 설명용 데이터로 촬영한다. 개인 메모·실제 사용자 기록·비밀 값은 포함하지 않는다. 불필요한 주변 화면과 빈 여백은 제거한다.
5. 검토한 이미지에 새 R2 경로를 부여하고 공개 응답을 확인한다. 매니페스트 URL과 실제 픽셀 크기를 갱신한다. 기존 객체를 덮어써 캐시된 이미지가 남는 방식을 피한다. 그림과 문구가 그대로라면 기존 이미지를 재사용한다.
6. PC 좌우 배치와 모바일 세로 배치, 그림 로딩, 텍스트 넘침, 설명과 실제 버튼의 일치를 확인한다. 손글씨 등 UI가 동적으로 바뀌면 전후 상태도 확인한다.
7. 기능·안내·이미지 매니페스트·관련 문서를 같은 커밋에 담는다. `docs/DEPLOYMENT.md`에 따라 GitHub에 푸시하고 Vercel Git 자동 배포 및 운영 화면을 확인한다.

## 완료 기준

- 안내의 버튼 이름·동작·일정·저장 규칙이 실제 구현과 일치한다.
- 바뀐 조작 화면이 이전 캡처로 남지 않는다.
- 이미지가 안내 안에 바로 표시된다. PC는 왼쪽 이미지/오른쪽 설명, 모바일은 위 이미지/아래 설명이다.
- 관련 기능 검사와 안내 표시 검사가 통과한다.
- 구현 문서와 재사용 스킬의 관련 규칙도 필요한 만큼 갱신한다. 스킬 사본 간 동기화는 담당자가 수행하는 작업이며 자동 폴더 동기화가 아니다.
- 완료 보고에 기능뿐 아니라 안내·캡처 갱신 여부와 검증 결과를 포함한다.
