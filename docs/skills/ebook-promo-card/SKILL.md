# 전자책 A5 홍보카드

## 공통 기획·카피 기준 (2026-10-02)

기존 스킬의 인쇄·출력 규격을 기본으로 유지하고 새 자료는 카피·이미지 기획 내용만 보완한다. 전자책의 HTML·아임웹 임베딩 방식은 변경하지 않는다. 인쇄용 홍보카드 PDF를 전자책 PDF 전환과 혼동하지 않는다.

프로젝트 루트 기준 `living-books/docs/EBOOK_CREATION_PROMPT.md`와 `living-books/docs/EBOOK_PROMPT_MODULES.md`의 P10~P14를 함께 적용한다. 앱 저장소 루트에서는 `docs/`부터 읽는다. 카드만 수정할 때 전체 책을 다시 기획하지 않는다. 후킹은 구체적인 독자 상황·실제 제공물·확인 가능한 첫 행동에서 만들고, 생성한 입금·검진·합격 화면을 실제 성과 증거로 쓰지 않는다. 확정되지 않은 가격·환불·희소성을 넣지 않는다.

본문 근거와 앞면 약속·뒷면 요약을 맞춘다. 광고용 4:5를 기존 카드의 3:2 이미지 규격에 강제하지 않는다. 제작 규칙 변경은 `living-books/docs/EBOOK_PROMPT_CHANGELOG.md`에 날짜·전후·이유·검증을 남기고 프로젝트 스킬과 `docs/skills/` 사본을 함께 갱신한다.

프로젝트의 `living-books/docs/PROMOTIONAL_CARDS.md`와 `living-books/public/promo/PROMPT.md`를 읽고 적용한다. 현재 34종이라는 수를 미래 제작에 고정하지 말고 `src/lib/promo-cards.ts`, 프리미엄 내보내기 목록, 홈의 공개 가이드를 대조한다.

- A5 148×210mm 양면 전단지. 앞면은 홍보카드, 뒷면은 해당 책의 서문 발췌 또는 핵심 요약이다. A5 PDF는 상품별 앞면→뒷면 순서이며 긴 쪽 넘김으로 인쇄한다. A4 가로는 같은 상품 앞면 2장→뒷면 2장과 중앙 재단선, 짧은 쪽 넘김이다. 먼저 한 쌍을 시험 인쇄한다.
- 뒷면 요약은 src/lib/promo-summaries.ts에서 관리하며 서문 직접 인용과 구분한다. 원고에 근거한 핵심 내용·읽기 순서·질문을 약 10.5pt 이상으로 담고 모든 뒷면의 잘림과 앞뒷면 상품 대응을 확인한다.
- 제목 두 줄, 보조 한 문장, 책 안에서 확인할 내용 두 줄, 실제 생성 이미지 한 장, CTA와 QR을 사용한다. 후킹은 구체적인 질문과 시각적 비유로 만들고 판매량·후기·성공·의학적 결과를 꾸며내지 않는다.
- 이미지에는 글자와 QR을 넣지 않는다. 한국어는 동봉 폰트로 조판하고 QR은 qrcode로 실제 생성한다. 4모듈 여백과 실물 30mm 이상을 유지한다.
- 기본 주소는 `https://vipup.site/상품ID`. 실제 연결과 QR 해독을 별도로 확인한다. HTTP 200·사이트 공통 제목만으로 해당 상품 연결을 보증하지 않는다.
- 한자 암기앱 ID는 hanja-memory, 전자책 ID는 hanja. 두 상품 소개와 카피는 구분하고 공통 한자 원고와 기존 학습 기록은 유지한다. 비교 부록은 전자책 전용이다.
- `scripts/export-promo-cards.mjs`로 개별/통합 PDF와 렌더 QR 검증을 실행한다. 실제 PDF 모든 페이지를 렌더링하여 잘림·이미지·글꼴·QR을 확인한다. 관리자 내보내기 다운로드까지 작동해야 완료다.
- 문구·주소·이미지 변경 시 PDF도 함께 재생성한다. 이미지 생성 프롬프트를 `public/promo/image-prompts.json`에 보관한다. 재사용 사용자 프롬프트 다운로드를 유지한다.
- 프로젝트 배포는 GitHub 푸시 → Vercel 자동 배포다. 사용자의 현재 배포 권한 범위에서 진행하고 실제 운영 주소를 확인한다.
