# 전자책 단계별 실행 프롬프트

버전 **2.0.0** · 2026-10-02 · 내용 보완 기준: [통합 프롬프트](EBOOK_CREATION_PROMPT.md)

**기존 제작 프롬프트와 전문 스킬이 기본이다.** 아래 모듈은 기획·목차·본문·부록·상세페이지를 보강한다. HTML·아임웹 iframe/코드 임베딩·뷰어·내보내기 방식은 변경하지 않는다. 전자책 PDF 전환은 수행하지 않으며 기존 인쇄 홍보카드 PDF만 해당 규격대로 유지한다.

아래 16개 모듈은 제공 자료의 문장을 복제한 모음이 아니라 우리 웹 전자책 제작에 맞춰 새로 작성한 실행 도구다. 필요한 모듈과 입력을 함께 사용한다. 모든 모듈에서 `사실 / 추론 / 가상 예시 / 미확인`을 구분하고, 앞 단계의 ID와 결과를 이어받는다.

## P01. 실제 질문 수집·정리

```text
역할: 독자 조사 담당자.
입력: [주제], [관심 커뮤니티/공개 링크/사용자 제공 질문], [기간], [독자 범위].
공개 접근 가능한 질문 10~15개를 목표로 수집하라.
권한이 없는 게시물에 우회 접근하지 말고 확보한 수만 보고하라.
제목의 ‘어떻게/도와주세요’뿐 아니라 반복 실패·비교·선택 질문도 포함하라.
같은 글의 재게시·광고성 글은 구분하고 실제 질문과 가상 예시를 섞지 말라.
원문은 분석에 필요한 짧은 구절만 쓰고 나머지는 요약하라.
출력 표:
Q-ID | 질문 요약 | 짧은 핵심 표현 | 상황 | 막힌 지점 | 바라는 결과 |
출처 URL 또는 파일/쪽 | 게시일·확인일 | 중복군 | 자료 유형.
끝에 실제 확보 수, 제외 사유, 표본의 편중, 더 확인할 질문을 적어라.
검색이 불가능하면 수집했다고 하지 말고 검색어·기록 양식만 먼저 제공하라.
```

## P02. 상위 3문제·한 명의 독자·해결 약속

```text
역할: 문제 정의 담당자.
입력: [P01 질문표], [실제 제공 가능한 지식·도구], [책의 제한].
질문을 3개 핵심 문제로 묶되 근거가 부족하면 억지로 3개를 채우지 말라.
빈도는 중복 제거 질문 중 해당 주제를 언급한 수/전체 수로 제시하라.
복수 주제 분류가 가능하면 합계가 100%를 넘을 수 있음을 밝혀라.
감정 강도 1~3을 별도 평가하라:
1=불편, 2=실행 중단·반복 실패, 3=질문에 명시된 긴급한 손실/곤란.
강도는 작성자의 임상 상태나 소득을 추정하는 점수가 아니다.
상위 문제마다 Q-ID, 직접 드러난 걱정, 추론한 두려움, 대안 설명을 적어라.
빈도·강도·우리가 실제로 도울 수 있는 범위를 함께 보고 핵심 문제 하나를 선택하라.
출력:
1) 세 문제 비교표와 우선순위 이유
2) ‘[상황] + [장애물] + [목표]’ 한 문장 페르소나
3) 독자의 시간·도구·선행지식·구매 전 질문
4) ‘[독자]가 [절차/도구]로 [검증 가능한 결과물]을 만든다’ 약속 1문장
5) 첫 10분 행동의 설계안과 완료 기준, 포함/제외 범위
6) 수요가 확인된 부분과 아직 가설인 부분.
```

## P03. 제목 20개·부제 확정

```text
역할: 제목 편집자.
입력: [P02], [실제 결과물], [근거 있는 숫자], [피해야 할 표현].
상황 공감/결과물/작은 시작/실수 예방/관점 전환의 다섯 각도에서 각각 4개,
총 20개의 서로 다른 제목을 작성하라. 단어만 바꾼 중복은 제외하라.
각 후보에 부제와 연결 결과물 ID를 붙여라.
명확성·독자 적합성·구체성·본문 근거·모바일 가독성을 각 0~2로 평가하라.
근거 0점 후보는 총점과 관계없이 보류한다. 점수는 매출 예측이 아니다.
상위 3개의 장단점을 설명하고 메인 제목 1개+부제 1개를 확정하라.
숫자·시간은 실제 항목 수나 측정값을 사용하고 목표 시간은 목표라고 표시하라.
‘평생 잊지 않음/무조건 합격/월수익 보장/누구나 즉시’는 넣지 말라.
출력: 후보표20행, 최종 제목·부제, 선정 이유, 검증 대기 문구.
```

## P04. 레퍼런스 역기획·분량 설계

```text
역할: 독창적인 목차 설계자.
입력: [P02·P03], [공개 목차 1~3개와 출처], [형식/분량], [제공할 실물].
참고 목차의 해결 순서·시작 난이도·실물 결과물·빈틈만 분석하라.
고유 제목·본문·사례를 복사하지 말고 우리 질문표에서 목차를 새로 설계하라.
순위가 확인되지 않았으면 ‘상위권/1등’ 대신 ‘참고 상품’으로 적어라.
일반 실무서는 진단→준비→실행→오류 해결→지속 활용의 5단계를 기본안으로 삼아라.
20개 소목차를 출발점으로 하고 적합하지 않으면 변경 이유와 대체 구조를 제시하라.
각 소목차 제목 끝에 [남는 결과물]을 붙여라.
표: 장/소목차 | Q-ID | 독자의 행동 | D-ID 결과물 | 선행조건 |
작성 예시 | 완료 기준 | 근거/검증 필요 | 예상 학습량.
한 소목차마다 서로 다른 실물 결과물을 억지로 늘리지 않아도 된다.
하나의 결과물을 단계적으로 완성한다면 각 단계에서 무엇이 채워지는지 적어라.
참고 강의의 20×2는 본문40쪽이라는 점만 검산하고 50쪽/PDF 출력 규칙을 도입하지 말라.
웹에서는 고정 쪽수가 아니라 하나의 행동 또는 학습 항목을 단위로 설계하라.
한자/어원 목록은 원문 전체와 중복 의미를 보존하고 20개로 강제 축소하지 말라.
```

## P05. 문체 설계·실무 인터뷰 질문

```text
역할: 집필 준비 에디터.
입력: [사용 가능한 참고 문단], [저자 실제 기록], [선택 소목차].
참고 글에서 설명 순서, 문장 호흡, 어조, 예시 배치의 일반 규칙을 5개 추출하라.
특정 작가의 고유 비유·문구·경험을 재현하지 말고 우리 문체 카드로 다시 적어라.
실무자에게 물을 질문을 최소 8개 작성하라:
초보의 첫 실패, 필수 준비, 실제 입력값, 예외, 실패 신호, 복구 순서,
버려도 되는 단계, 완료 판정과 그 근거를 포함하라.
실제 답변이 있으면 핵심 노하우 3개를 답변 위치와 함께 정리하라.
답변이 없으면 ‘AI가 만든 실무 가설’ 3개와 확인 방법을 제시하라.
AI 역할의 경력·고객·매출을 저자의 이력이나 실제 인터뷰처럼 쓰지 말라.
출력: 문체 카드, 질문지, 확인된 노하우/검증할 가설, 본문에 넣을 위치.
```

## P06. 출처 교차 검증·주장 장부

```text
역할: 사실 검증 에디터.
입력: [원고 또는 주장 목록], [참고 자료], [대상 국가·플랫폼·기준일].
중요한 수치·효과·법령·정책·가격·인용·절차를 빠짐없이 C-ID로 추출하라.
S-ID 출처표: 기관/저자, 문서명, 원문 URL 또는 파일/쪽,
발행·수정·확인일, 해당 위치, 적용 대상, 출처 유형.
주장표: C-ID | 원문 주장 | S-ID | 근거 요약 | 조건·예외 |
확인/부분 확인/충돌/미확인 | 수정 문장 | 적용 위치 | 재확인 계기.
핵심 주장에는 가능한 독립 출처를 교차 비교하고 공식/1차 자료를 우선하라.
세 자료가 서로 인용한 같은 출처라면 독립 근거 수를 부풀리지 말라.
법·정책·도구 기능 등 변하는 내용은 작성 시점의 공식 정보를 확인하라.
확인할 수 없으면 그 사실을 적고 공개 문장을 삭제하거나 범위를 줄여라.
명언은 발언자 이름만 믿지 말고 원출처를 찾고, 없으면 인용부호와 귀속을 제거하라.
매출과 순이익, CTR과 전환율, ROAS와 이익률을 구분하여 계산하라.
면책 문구로 틀린 내용이나 미확인 효과를 유지하지 말라.
출력: 두 장부, 충돌 처리, 공개본에서 보류할 문장, 다음 확인 항목.
```

## P07. 소목차 본문·실물 부록

```text
역할: 초보자를 위한 실무 집필자.
입력: [P04의 소목차 1개], [P05 문체], [P06 근거], [실제 화면/도구].
첫 문장에 핵심 답을 말하고 다음 순서로 완성 원고를 작성하라.
핵심 답 → 사용할 상황 → 준비물 → 번호 있는 실행 순서 → 작성 예시 →
자주 막히는 지점과 대안 → 스스로 확인할 질문 → 오늘 할 행동 1개.
조작 안내에는 실제 버튼명, 입력 내용, 정상 결과, 실패 시 돌아갈 위치를 적어라.
확인하지 않은 UI나 성공 경험을 만들어내지 말라.
예시에는 실제/가상의 구분을 붙이고 개인정보를 제거하라.
선택한 소목차에 필요한 체크리스트 또는 복사 양식을 실물로 작성하라.
빈 양식, 작성 예시, 사용 시점, 끝났다고 판단할 기준을 모두 포함하라.
참고 자료의 인쇄 2쪽 목표를 웹 본문에 강제하지 말고 필요한 설명을 완결하라.
출력: 완성 본문, D-ID 부록, 근거 연결표, 미검증 부분.
```

## P08. 군더더기 교정·정확성 보존

```text
역할: 문장 편집자.
입력: [초안], [독자], [반드시 유지할 조건·수치·예외·출처].
예고형 서두를 덜고 답부터 시작하라. 불필요한 ‘매우 중요합니다’는
실제 행동이나 이미 근거가 있는 문제 상황으로 바꾸어라.
짧은 능동문을 기본으로 하고 쉼표가 많으면 의미 단위로 나누어라.
30~45자는 권장값일 뿐 이름·인용·조건문을 억지로 자르지 말라.
한 문단에 한 주제를 담고 소제목·목록·팁 박스는 읽기에 도움이 될 때만 사용하라.
접속사 제거 비율이나 ‘두 줄’ 목표를 위해 논리와 조건을 삭제하지 말라.
추상어를 구체화할 때 없는 금액·기간·성공률을 보충하지 말라.
공포·죄책감·독자 비난을 문제 인정과 실행 가능한 다음 행동으로 바꾸어라.
출력: 완성 본문, 대표 전후 비교 3개, 유지한 주의사항, 새 주장 발생 여부.
```

## P09. 기억 장면·회상 학습

```text
역할: 메모리학습 콘텐츠 설계자.
입력: [원문 항목/훈음 또는 단어·어원], [검증 출처], [독자], [기존 ID].
원문은 보존하고 교정 사항은 원문·수정·이유·출처 표로 먼저 기록하라.
뜻의 핵심을 즉시 떠올릴 단독 장면 하나를 정하고 특징 하나를 과장하라.
장면 선택 이유, 짧은 연결 문장, 활용 예시 2개, 가리고 회상할 질문,
정확한 정답, 혼동 주의, 한글/영문 이미지 프롬프트를 작성하라.
창작 암기법과 역사적 어원은 별도 필드로 구분하라.
단어 예시는 실제 쓰임을 확인하고 학습자의 수준에 맞춰라.
훈음 첫 글자 고르기는 단서형 시험이며 완전 회상과 같다고 설명하지 말라.
이미지는 스타일·주대상·색·질감·과장 특징·구도·흰 배경·피사체 전체를 지정하라.
한글 100~150자 등 사용자가 지정한 길이는 실제로 세고 영문과 의미를 맞춰라.
부수·희귀자·같은 표기의 다른 뜻은 임의 합치지 말고 안정적 ID로 구분하라.
공통 항목은 앱·전자책에, 비교 부록은 전자책에만 연결하라.
출력: 검수 가능한 항목표와 생성/회상 검증 기준. 실제 동기화는 전용 스킬을 따른다.
```

## P10. 표지·3D 목업·삽화 아트디렉션

```text
역할: 출판 아트디렉터.
입력: [제목·부제], [독자·핵심 문제], [실제 제공물], [사용 채널], [시각 정체성].
이미지 목적을 평면 표지/3D 목업/학습 삽화/광고 히어로 중 하나로 먼저 고정하라.
타깃 상황, 한 장면, 초점, 대비, 색상, 조명, 재질, 구도, 여백을 설계하라.
스타일 선택지는 타이포 중심/사용 상황/실제 화면/행동 비교/일상 장면/
```
